Layout leftovers — bug "layoutfix"
==================================
Visual-only CSS fix for four overlapping stage overlays. No behaviour, IDs or clicks changed.

Measured live in Chrome against this worktree's server (PORT 8795 from .env, production
`npm run build` + `npm start`, one port, client + websocket) with the build theater streaming
its code card. Rects are `getBoundingClientRect()` in CSS px. "clear" = the rect does not
intersect the other one.

What the card streams in the screenshots
- `window.preview_idle_fx()` — the app's own canned build, pushed through the same
  `theater.onMsg` path as a real one (no API call). Both the before and the after screenshots
  use it, so the two sets are directly comparable.
- Two real Meta builds were also run live on this branch and measured while streaming:
  "add a bouncing green slime" (before: `.bt-card` 800..1220 y 68..144) and
  "add a spinning coin" (after: `.bt-card` 800..1220 y 170..270, then the receipt in
  after-1280x720-receipt.png is that build's real receipt: Muse Spark 4.4 s, Muse Wonder
  5.0 s, verifier 0.0 s).

The starter world only declares top-left HUD widgets (health, score), so the top-right row
that bug 3 is about (level progress + a score stat) was injected for the measurement with the
app's own markup and classes (`.hud-pos.hud-pos-top-right`, `.hud-widget.hud-bar`,
`.hud-widget.hud-stat`) — the same nodes `src/client/hud.ts` builds for `position: "top-right"`
widgets (`src/sim/level.ts` sets the level bar there). The second-opinion fix card is
transient (5 s, only after a real review finds a bug), so its exact markup from
`src/client/second-opinion.ts` (`.so-card` with `<b>/<p>/<i>`, a deliberately long issue
sentence) was placed in `#second-opinion[data-state="card"]` for the geometry check.
Everything else is the unmodified app.

The fixed geometry (after)
- `.bt-stream` (code card): top 170 px (was 68), bottom 48 px, card max-height 100%.
  170 clears the stepper (bottom 114..119) and the top-right HUD (bottom 157); 48 stops the
  card above the bottom row (key hint, pipeline button, timeline) on a short stage.
- `.hud-pos-top-right`: top 62 px in both drawer states (the `#app.drawer-hidden` override to
  106 px is gone). The row now always sits above the card.
- `#receipt-panel`: right 60 px (was 14) + width `min(460px, calc(100% - 74px))`, and the
  <=900 px rule uses `right: 60px` (was 10). It ends 8 px left of #quickbar.
- `#explain-panel`: width `min(380px, calc(100% - 82px))` and `right: 60px` in the <=900 px
  rule. Same 8 px gutter.
- `#second-opinion`: top 124 px (was 76). On a narrow stage the centred stepper reaches into
  the left column (x 253..647 at 900x600), so the card used to cover its first two pips.
- `@media (max-height: 640px)`: the card's padding and gap shrink, the long "Wonder · …"
  status is dropped and the code area is capped at 96 px, so a 330 px-tall stage (900x600)
  still shows the head, the step chips and ~3 code lines instead of overflowing.

Known overlaps left alone (not in this bug, unchanged by it)
- #receipt-panel / #explain-panel are user-opened panels and still cover the ambient layers
  under them (the top-right HUD stats, and the code card while it streams). Only their
  overlap with the quick-action column was in scope.
- #explain-panel (top-left, 380 px) and the second-opinion card (top-left, 360 px) share the
  left column and can overlap each other; that predates this change.
- On the 330 px-tall stage at 900x600 the ghost playtest window (bottom-left) can sit under
  the second-opinion card, as it did before.
