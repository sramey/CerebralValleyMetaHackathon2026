Quick-action bar layout check — bug "qblayout"
===============================================

Measured live in Chrome against this worktree's dev servers (vite 5185, game server ws 8795),
with the build theater streaming its code card (`window.preview_idle_fx()`).
Rects are `getBoundingClientRect()` in CSS px; "clear" = the rect does not intersect #quickbar.

The bar is always one column on the right edge: right 12 px, 40 px wide, top 106 px,
three 40 px circles with 8 px gaps (136 px tall). The code card (.bt-stream) and the
top-right HUD (.hud-pos-top-right) end 8 px left of it (right: 60px).

Notes
- The starter world only declares a top-left health widget, so the top-right HUD row
  (level progress + score) and the top-centre banner were injected for the measurement
  with the app's own classes (`.hud-pos-top-right`, `.hud-widget.hud-bar`, `.hud-widget.hud-stat`,
  `.hud-pos-top-center`, `.hud-widget.hud-banner`) — see after-1280x720-hud-banner-clear.png
  and after-900x600-hud-banner-clear.png. Everything else is the unmodified app.
- The card itself still sits over the top-right HUD while it streams (it is above it,
  z-index 23 vs 22). That overlap predates this bug and is not caused by the quickbar.
- Accessibility: `take_snapshot` reports `navigation "Quick actions"` with three buttons
  named "What it has learned", "Draw a level" and "Bring an object in (camera)", each
  carrying its `title` as the description.
