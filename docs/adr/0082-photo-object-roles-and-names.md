# ADR 0082: A photo object gets a role and keeps its name

- **Status:** Draft
- **Date:** 2026-11-01
- **Supersedes:** nothing. Extends the photo template of ADR 0010 and the wire of ADR 0081.

## Context

After ADR 0081 the cut was good, but every brought-in object was the same thing: a hopping prop whose entity
type was `photo-N`. The owner wanted to say what it is (a pickup, an enemy, a friend) and to talk about it
afterwards. "Make the learning toy bigger" went to Wonder, which wrote a second mod; the radial menu read
"make photo-1"; Wonder's manifest and `inspect_world` showed an entity called `photo-1`.

## Decision

- **Role.** The camera dialog has a compact select next to Pixel-art style: Prop (default), Collectible, Enemy,
  Friendly. The last choice is remembered for the session (sessionStorage, optional).
- **Wire (additive).** `photoBring` and `photoBringLocal` gain `role` and (local only) `slug`. The server
  validates the role against the four values (anything else is Prop) and the slug against a short
  `[a-z0-9-]` pattern (anything else is dropped, and the type stays the photo key). Old clients keep working.
- **Templates.** The mod is still generated by the server from a template, compiled and verified, with no model
  call (`server/photo-mod.ts`). Each role follows the engine's conventions and ships a `test()`:
  - Collectible: `data.collectible: true` (ADR 0055), no gravity, a small bob; the engine counts and despawns it.
    A pickup-into-inventory (ADR 0074) was not used: gear needs a use and a slot, which is more than "touch it".
  - Enemy: `data.hostile: true`, health 30, chases the player; contact damage and stomp are the engine's
    (`world.ts`), shots use `combat.ts`.
  - Friendly: `data.friendly` and `data.pet` (`isFriendly`, `isPet`), follows the player; player fire never
    damages it (`combat.ts`).
  - Prop: today's hop, now with a Jump height knob. Every role has a Size knob.
- **Name.** The spoken name (what the player typed, else Spark's) is the mod title, `data.name`, and the entity
  type as a readable slug ("learning-toy"), so Spark's router, Wonder's manifest and `inspect_world` all see it.
  The radial label reads it too.
- **Texture follows the type.** The client matches textures to entity types by name (`framesFor`), so it
  registers the cut under the slug as well as the photo key. It picks a free slug (no clash with art or
  another entity), keeps these slugs out of mood restyling, and prefixes `my-` when the name alone would make
  the engine treat the object as a pet or an enemy the player did not choose (`photoSlug`).
- **Names the engine draws as shapes** ("gem", "ball") would hide the cut-out, so those keep the `photo-N`
  type; the title and `data.name` still carry the name.
- **Size and jump by name.** `relative-tweak` gains a "size" dimension ("make the learning toy bigger") for a
  *named* thing only; "make me bigger" and "make it bigger" stay with the router. A named ask now tweaks the
  photo mod's own knob instantly instead of costing a Wonder build.

## Consequences

- One more wire field pair and a shared pure module (`src/photo-role.ts`).
- Typed names win over Spark's guess in the dialog, since they are what the player will say.
- Photo textures still do not survive a reload (unchanged), so a reloaded object is a rectangle until re-brought.
- A named size ask on any mod without a size-like knob now becomes an edit of that mod instead of a new build.
- The engine's enemy contact damage is 10 per hit with a 0.6 s window, so an unshot chaser is lethal in seconds.

## Evidence

`docs/evidence/photorole/` (live run on the dev ports with drawn, person-free fixtures) and
`tests/photo-roles.test.ts` (each template compiles, verifies and behaves; wire validation; router asks).
